# 账号：自动注册 / 登录 / 凭据存储

## 凭据库

路径：`.ugc-publisher/accounts.json`（相对项目根；已加入 .gitignore）

```json
{
  "default": "ugc_8f3a2c",
  "accounts": [
    {
      "username": "ugc_8f3a2c",
      "password": "Kf9-mQx2-pL7s",
      "nick": "冲浪选手8f3a",
      "created": "2026-09-19T10:00:00Z",
      "lastLogin": "2026-09-19T10:00:00Z",
      "note": "自动注册"
    }
  ]
}
```

规则：
- 文件不存在则创建；注册成功后追加账号，首个账号写入 `default`。
- 每次登录成功更新 `lastLogin`。
- 文件含明文密码：写入后执行 `chmod 600 .ugc-publisher/accounts.json`；不要把它写进任何帖子、日志或提交。
- Read/Edit 该文件时用本地文件工具，不要把内容贴到浏览器页面里。

## 生成账号（用户未指定用户名时）

- username：`ugc_` + 6 位小写字母/数字，例 `ugc_8f3a2c`（满足 `^[a-zA-Z0-9_]{3,20}$`）。
  生成前用 page-map 里的 evaluate 片段查 `wb_sim_users`，若已被占用则重新生成。
- password：12 位随机字母数字与符号（页面仅要求长度 ≥6，避免使用空格/中文/引号，免得出输入意外）。
- nick：`冲浪选手` + 4 位字符（≤20 字、非空即可）；用户给了昵称偏好就用用户的。

## 注册操作序列（页面内）

1. 打开注册弹窗（二选一）：
   - 游客：点 `#openReg`（右上角"注册"）；
   - 登录弹窗已开着：点 `#authSwitchLink` 切到注册模式（看 `#authTitle` 变成"注册微博"、`#nickField` 可见）。
2. `browser_type` 依次填 `#regNick`、`#authUser`、`#authPass`。
3. 点 `#authSubmit`（"注册并登录"）。成功后弹窗自动关闭并 toast"注册成功"。
4. 成功后立即把凭据写入凭据库并 chmod。

## 登录操作序列

1. 点 `#openLogin` 或 `#guestLoginBtn`（标题为"登录微博"，`#nickField` hidden）。
2. 填 `#authUser`、`#authPass`，点 `#authSubmit`（或密码框回车）。
3. 成功：弹窗关闭、toast"登录成功"、`wb_sim_session` 有值。

## 错误处置

| `#authErr` 文本 | 含义 | 处置 |
|---|---|---|
| 用户名需为 3–20 位字母数字或下划线 | 用户名不合规 | 自动注册场景换一个合规用户名；用户指定场景则让用户修改 |
| 密码至少 6 位 | 密码过短 | 自动生成的密码不可能触发；若触发说明流程有 bug，记录 lessons |
| 请填写昵称 | 昵称为空 | 补一个默认昵称重试 |
| 用户名已被占用（注册时） | 名字撞了 | 自动生成场景：换随机后缀重试，最多 3 次 |
| 用户名或密码错误（登录时） | 凭据库密码与页面不符 | ①先用凭据库里其他账号；②若用户指定的就是该账号，停止并向用户报告（页面 hash 不可逆，无法找回），**不要反复试密码**，把现象记入 lessons |

## 决策表（与 SKILL.md 步骤 3 一致）

1. 已登录 + 未指定用户名 → 直接发帖。
2. 已登录 + 指定了不同用户名 → `#logoutBtn`，再按 4 处理。
3. 未登录 + 指定用户名：
   - 凭据库有 → 登录；登录失败按上表处理；
   - 凭据库无 → 视为新账号：用该用户名注册（昵称取用户名或用户偏好，生成密码并入库）。
4. 未登录 + 未指定用户名：
   - 凭据库有 `default` → 直接登录 default（复用账号，避免无限注册）；
   - 凭据库为空 → 生成并注册新账号，记为 default。

> 注意：登录态在 localStorage 里，Playwright 新开的浏览器上下文可能是空的，
> 所以每次会话**先查 `wb_sim_session`**，没有就优先用凭据库 default 登录，而不是直接注册新号。
